# 翻译准确度与速度实测

测试日期：2026-11-20。48 句常见商务会议用语，四个方向各 12 句：中→西、西→中（含阿根廷口语）、中→英、英→中。
句子在 [`scripts/dev/bench-cases.json`](../scripts/dev/bench-cases.json)，大模型那一组可以用 [`scripts/dev/bench-zhipu.mts`](../scripts/dev/bench-zhipu.mts) 自己重跑。

- **离线翻译**：本软件内置的免费离线翻译（Mozilla 模型），在普通电脑的浏览器内核里运行。
- **本机 AI 翻译**：腾讯开源的翻译模型 Hy-MT2-1.8B（Apache-2.0，4 位量化，1.1 GB），用 llama.cpp 在电脑上运行。测试机是 4 核服务器 CPU、没有显卡（苹果 M 系列芯片会更快）。
- **大模型**：智谱 GLM-4.7-Flash（免费），走本软件自己的翻译代码，一句一句地发。
- **评分**：逐句人工检查。✓ 意思完全正确；△ 能看懂，但有小错或不通顺；✗ 意思错了。

## 结果

| | 离线翻译（免费） | **本机 AI 翻译（免费）** | 智谱大模型（免费 Key） |
|---|---|---|---|
| 需要 | 下载 140 MB | 下载 1.1 GB | 联网 + Key |
| 每句耗时（中位数） | **0.06 秒** | 约 1 秒 | 0.9 秒 |
| 最慢一句 | 0.1 秒 | 2.3 秒 | 2.9 秒 |
| ✓ 完全正确 | 32 / 48（67%） | **44 / 48（92%）** | 44 / 48（92%） |
| ✓ + △ 能看懂 | 44 / 48（92%） | **48 / 48（100%）** | 48 / 48（100%） |
| ✗ 意思错 | 4 句 | 0 句 | 0 句 |

分方向（✓ / △ / ✗）：

| 方向 | 离线翻译 | 本机 AI 翻译 | 智谱大模型 |
|---|---|---|---|
| 中→西 | 8 / 3 / 1 | 11 / 1 / 0 | 11 / 1 / 0 |
| 西→中 | 7 / 3 / 2 | 10 / 2 / 0 | 10 / 2 / 0 |
| 中→英 | 8 / 3 / 1 | 12 / 0 / 0 | 12 / 0 / 0 |
| 英→中 | 9 / 3 / 0 | 11 / 1 / 0 | 11 / 1 / 0 |

本机 AI 翻译的 4 个小问题：“de adelantado”应为“por adelantado”；“他们什么时候能交付”应为“你们”；“Dale”翻成“戴尔”（软件翻译前会先把它换成标准西语，换完就对了）；“样本”应为“样品”。

### 更大的本机模型：Hy-MT2-7B（可选）

同一套 48 句，换成同系列的 7B 模型（4 位量化，4.6 GB）：

| | Hy-MT2-1.8B（默认） | Hy-MT2-7B |
|---|---|---|
| 需要 | 下载 1.1 GB | 下载 4.6 GB，内存 8 GB 以上 |
| 每句耗时（中位数，4 核 CPU） | 约 1 秒 | 4.9 秒 |
| 最慢一句（4 核 CPU） | 2.3 秒 | 16.2 秒 |
| ✓ 完全正确 | 44 / 48（92%） | **46 / 48（96%）** |
| ✗ 意思错 | 0 句 | 0 句 |

7B 把 1.8B 的“de adelantado”“他们什么时候”“样本”三处都翻对了，剩下两个小问题：“Dale”翻成“戴尔”（软件会先换成标准西语）；“llegaron cajas rotas”翻成“箱子都是破损的”（原意是“有些箱子破了”）。
在普通 CPU 上 7B 太慢，跟不上同传，所以软件只在苹果 M 系列芯片的 Mac 上提供这个选项（用显卡加速；这台测试机没有 Mac，Mac 上的速度没有实测）。

为什么不“训练”离线翻译：重新训练翻译模型需要大量双语语料和显卡跑很多小时，不适合在每个人的电脑上做。换成更新、更好的开源翻译模型，再配合你的术语表和纠错字典，效果更好也更省事。

大模型的速度和当时的网络、服务器繁忙程度有关：这次每句约 1 秒；之前测试时遇到过限流，单句要等好几秒。

## 离线翻译典型错误

- “这个方案你们觉得怎么样？” → “¿Qué te parece este *programa*?”（“方案”应为 propuesta / plan）
- “质量问题我们负责免费更换。” → 意思乱了
- “Necesitamos la factura antes de que llegue la mercadería…” → “我们需要……之前*支付账单*”（应为“拿到发票”）
- “¿El producto tiene certificación para vender en Argentina?” → 漏掉了“认证”
- “…el flete hasta Buenos Aires” → “*飞往*布宜诺斯艾利斯的运费”

这些错误在两段式翻译里会被大模型的正式译文替换掉；只用离线翻译时，可以把常用词加进术语表（例如 方案 → propuesta、flete → 运费），之后都会按你的写法翻。

## 阿根廷口语

离线模型本身能看懂 vos 的变位（tenés、querés、podés），但会把几个常用口头语翻错，例如 Che → “切”、Dale → “戴尔”、Bárbaro → “巴巴鲁斯”、Nos parece bien → “我们很好”。
现在离线翻译前会先把这些说法换成标准西语（Che 去掉；Dale → De acuerdo；Listo → Bien；Bárbaro → Genial；Ojo → Atención；re caro → muy caro；¿viste? 去掉；me/nos parece bien → estoy/estamos de acuerdo；laburo → trabajo；me pasás → me das），这几句就都翻对了。只在这些词单独作口头语时才换，“Dale el catálogo a Juan”“El pedido está listo”这类正常用法不动。

## 0.9 提速（2026-11-21）

同一台 4 核服务器 CPU、同样 2 个线程（软件在 4 核电脑上的默认值），48 句两个方向交替翻译，走软件自己的翻译代码（[`scripts/dev/latency-bench.mts`](../scripts/dev/latency-bench.mts) 可以重跑）：

| | 改之前 | 改之后 |
|---|---|---|
| 每句耗时（中位数） | 2.66 秒 | **1.23 秒** |
| 90% 的句子在 | 3.77 秒内 | **1.88 秒内** |
| 最慢一句 | 5.2 秒 | 3.4 秒 |
| 第一句 | 3.35 秒 | 1.80 秒 |
| ✓ 完全正确 | 45 / 48 | **46 / 48** |
| ✗ 意思错 | 0 | 0 |

改了什么：
- 去掉了翻译库默认加在每句前面的英文“系统提示”（约 55 个词元，模型训练时并没有它），改用 Hy-MT 自己的对话格式。
- 两个方向各用一条通道，各自的“指令”部分算一次就留着，新的一句只算它自己的字；两个方向可以同时翻。
- 逐句人工复核：48 句里 22 句措辞有变化，没有一句变差；“samples”从“样本”变成了“样品”，“两年期的保修期”变成了“两年保修期”。剩下的两个小问题和以前一样：“de adelantado”应为“por adelantado”，“你们”译成了“他们”。

### 线程分配（同一台 4 核电脑，2026-11-21）

翻译和识别抢的是同一份 CPU，所以分别测了“单独跑”和“西语识别一直满负荷跑”的情况（Whisper-small 每次识别 6 秒西语，循环不停，是最坏情况）：

| AI 线程 + 识别线程 | AI 每句（中位数 / 90%） | 识别 6 秒西语 |
|---|---|---|
| AI 单独：2 线程 | 1.32 / 2.05 秒 | — |
| AI 单独：4 线程 | **0.68 / 1.16 秒** | — |
| 识别单独：2 线程 | — | 2.2 秒 |
| 识别单独：4 线程 | — | 1.7 秒 |
| 同时满负荷：AI 4 + 识别 4 | 0.71 / 2.00 秒 | 4.1 秒 |
| 同时满负荷：AI 4 + 识别 2 | 0.67 / 1.68 秒 | 3.5 秒 |
| 同时满负荷：AI 2 + 识别 2（以前的默认） | 1.23 / 2.03 秒 | 2.0 秒 |

开会时识别和翻译大多是先后进行的（一句话先识别、再翻译），很少同时满负荷，所以：
- **本机 AI 用全部“适合计算的核心”**（性能核，不算超线程），最多 8 个；进程是“稍低”优先级，会议软件始终优先。4 核电脑上每句从 1.3 秒降到 0.7 秒。线程数不影响结果：48 句 2 线程和 4 线程的译文逐字相同。
- **西语/英语识别**在 6 个以上逻辑核心的电脑上用 4 线程，否则 2 线程；中文识别（SenseVoice 很轻）保持 2 线程。
- **西语/英语一段话最长 6 秒**（以前 10 秒）：超过 6 秒就在下一个短停顿处切开（不在词中间切），前半段先识别、翻译，说话人继续说。
- （西语/英语识别后来换成了 Parakeet，见下一节：快得多，也能边说边出字了。）
- 这台电脑翻译确实慢时（最近 6 句里有 4 句超过 4 秒或超时），会议页会明确提示一次，说明对方会晚听到、太晚的句子只显示字幕不念，以及怎样更快（换云端方案、关掉占电脑的软件）。不会悄悄换成别的翻译。

## 西语 / 英语识别：Whisper small → Parakeet（2026-11-21）

上面量下来，西语那一边最慢的是识别（Whisper small）：说完要等 2.7 秒才出文字。换成 NVIDIA 的 Parakeet-TDT 0.6B v3（CC-BY-4.0，可商用，sherpa-onnx 的 int8 版，671 MB）。

**准确率**：40 句阿根廷口音西语（Google 众包录音，男女各 20 句，不同说话人，带标准文本），同一台 4 核电脑：

| | 词错误率（不计重音） | 词错误率（计重音） | 有错的句子 | 每句识别耗时（中位数，约 5 秒的话） |
|---|---|---|---|---|
| Whisper small（以前） | 7.6 % | 10.0 % | 13 / 40 | 1.35 秒 |
| **Parakeet v3** | **2.7 %** | **4.9 %** | **8 / 40** | **0.34 秒** |

Parakeet 剩下的“错”大多不算错：把“catorce”写成“14”、把阿根廷说法“podés”照实写出来（标准文本写的是“puedes”）、标准文本自己的笔误（“las más dura”）。Whisper 有整句听乱的：“Los cabecillas de la banda huyeron a caballo”被识别成“Tocas las zichas de la banda y ushérenla con la soja”。英语样句两者都对，Parakeet 快 5 倍。

**说完 → 译文出来**（真人录音按实时速度送进软件自己的流程：语音检测 + 识别 + 本机 AI 翻译；不含语音合成，[`scripts/dev/e2e-latency.mts`](../scripts/dev/e2e-latency.mts) 可以重跑）：

| | 以前（Whisper small） | 现在（Parakeet + 边说边出字） |
|---|---|---|
| 西→中：识别出文字 | 说完后 2.7 秒 | 说话中就出（说完前约 0.6 秒已有第一句） |
| 西→中：第一句译文可以开始念 | 说完后 4.0 秒 | **说完时（+0.0 秒）** |
| 西→中：整段译完 | 说完后 4.0 秒 | **说完后 1.4 秒** |
| 中→西（一句没有停顿的短句） | 说完后 2.0 秒 | 说完后 1.9 秒 |

为什么快这么多：
- Parakeet 识别 1 秒话只要约 70 毫秒，所以说话过程中每秒重算一次“到目前为止说了什么”也不费力。
- 中间结果里已经说完的一句（句号、问号、逗号处，稳定 0.7 秒且有 4 个词以上）先送去翻译；说完时只剩最后一小句。
- 中间结果和最终结果只差重音（qué / que）、或把句号改成逗号时，算同一句话，不会把前半句再翻一遍。

**术语表里的词当“热词”**：Parakeet 是转换器模型，可以在识别时“留意”指定的词（sherpa-onnx 的束搜索 + 热词）。测试：被识别成“VC”的“bici”加为热词后识别正确；“champú/shampoo”两种写法模型很确定，没改。束搜索每次识别约慢 1.7 倍（5 秒话 0.28 → 0.5 秒），所以只在术语表里有西语/英语词时开启，最多 100 个。中文的 SenseVoice 不支持热词，中文继续靠术语表的读音纠正。

以前下载过 Whisper 的老用户：升级后会自动下载 Parakeet，下载好之前继续用 Whisper（会议页会说明），下好后自动换上，Whisper 可以在“存储空间”里删掉。

## 上下文与口语顺滑（2026-11-21）

**上下文**：一场会议的两个方向共用一份“对话记录”，只放双方说的原话（去掉口头语），不放机器译文——这样一句翻错不会带偏后面的句子。本机 AI 用 Hy-MT2 模型卡上的“背景信息”格式，对话在前、术语在后；只追加，最多 4 句、约 240 字，满了从最近 2 句重新开始。测试集和脚本：[`context-cases.json`](../scripts/dev/context-cases.json)（12 句必须靠上文才能译对的句子）、[`prompt-eval.mts`](../scripts/dev/prompt-eval.mts)。

| | 不带上下文 | 带上下文 |
|---|---|---|
| 12 句上下文题 | 约 5 句对（“电池是一年”译成“电池能用一年”；“No, eso va aparte”译成“那另当别论”；宾语阴阳性错） | 12 句都对（“电池保修一年”“需要额外收费”“ya las enviaron”“se lo enviaré a Juan”） |
| 48 句标准集：意思错 | 2 句（“Dale”译成“戴尔”，“Che”译成“切”） | 0 句 |
| 48 句标准集：措辞略别扭（意思对） | 2 句 | 3 句 |
| 术语表（5 句） | 5 / 5 | 5 / 5 |
| 每句耗时（中位数，4 核，会议节奏） | 0.67 秒 | 0.90 秒 |

另外加了一道检查：带上下文的译文里如果混进了原文没有的外文单词（测试中出现过一次“感谢您的 waktu”）或提示词里的标签，就不带上下文重翻一次。

**说错又改正**（“下周，不对，下个月”）：试了 Hy-MT2 的“个性化要求”格式，1.8B 模型做不到（10 句都照原样译出改口，和背景信息合用时还会去译上文），所以本机模型不用这个指令；云端大模型的提示里加上了“只译最终意思”，并附上双方上文、阿根廷西语的说明（vos、che、dale、quilombo…）。

**口头语和重复**（规则，翻译前处理，会议记录保留原话）：去掉呃、嗯、额、怎么说呢、eh、este…、mmm、um、uh 这类确定是口头语的词，合并紧挨着说了两遍以上的代词、连词（我们我们我们、el el、the the）。保守：单独一句“嗯。”（表示“是”）、“Eh?”（表示“什么？”）不动；谢谢、看看、研究研究、muy muy、had had、电话号码里的数字不动；este producto、额度、好啊、对吧不动。60 句测试（中西英各 20 句，[`tests/fixtures/disfluency.json`](../tests/fixtures/disfluency.json)）全部通过。

## 结论

- **本机 AI 翻译**（免费方案的默认翻译）：准确率和云端大模型一样，不联网、不用 Key、会议内容不出电脑，4 核电脑上每句约 0.7 秒。开会前就加载好，会议进行中一直保持加载。
- **离线翻译**最快（说完就出），只作为“先出的草稿”。AI 模型还没下载好时，不会用它凑合开会：会议页会提示下载进度，下载完再开始（等不及可以换云端方案）。
- 软件会先显示离线草稿（灰色斜体），AI 或大模型的译文到了再替换、再念；超过 8 秒没回或出错，草稿留作字幕（标注“草稿”），不念给对方。
- 术语表对三种翻译都生效：本机 AI 翻译会把你的术语当作“参考译法”。
