# 安全检查报告

检查日期：2026-11-20。范围：电脑版（Mac / Windows / Linux）、Chrome 插件、安卓 App、网站、GitHub 自动构建和发布流程。

## 一句话结论

没有发现能被别人远程控制你电脑、偷看你屏幕或在软件里植入病毒的漏洞。检查中找到的问题主要集中在两类：

- **从网上下载再运行的东西有没有被调包**：虚拟声卡驱动、公网链接工具、语音识别模型。
- **局域网“现场房间”的使用上限**。

这些都已经修好，并且写了自动测试，以后每次改代码都会再检查一遍。另有几件事需要你决定（见文末），它们不是漏洞，而是“能不能更进一步”。

## 怎么检查的

1. **独立的代码审查。** 另开一个审查者，从头读所有代码，像攻击者一样想：
   - 恶意网站、同一台电脑上的其他程序、同一个 Wi-Fi 里的人、被篡改的下载文件、被入侵的依赖包，分别能做什么？
   - 每个发现都要指出具体代码位置和利用方式。
2. **依赖包漏洞扫描**（npm audit）：0 个已知漏洞。
3. **核对随软件发布的二进制文件。** 离线翻译引擎（wasm）、Gradle 构建工具和官方发布的校验值逐一比对，完全一致。
4. **自动测试：** 320 个单元测试，12 个端到端测试（含 1 个用真实本机 AI 翻译模型的测试）。
   - 端到端测试真的打开软件、开会、录音、翻译。
   - 每次改代码，在 Linux、Mac、Windows 三种真机上都跑一遍，包括真实 AI 模型和系统语音。
   - 每次发布前，每个平台都用“打包好、上了锁”的安装版开一场会、用 AI 模型翻译，通过了才发布；发布后再下载发布出去的文件测一遍。

## 已经修好的问题

| 严重程度 | 问题 | 现在的做法 |
|---|---|---|
| 高 | Windows 一键安装 VB-CABLE 时，下载的安装包没有校验，就以管理员身份运行 | 安装包按我们核对过的 SHA-256 校验。<br>运行前在同一条管理员命令里，再核对一次安装程序的指纹和数字签名（必须是 VB-Audio 作者的 EV 签名），对不上就停止。 |
| 中 | Mac 安装 BlackHole：校验后到安装前，文件理论上能被换掉 | 在管理员权限下、安装前那一刻，再核对一次指纹和苹果开发者签名（Existential Audio，Q5C99V536K）。<br>文件放在随机的私有临时文件夹里。 |
| 中 | “公网链接”用的 cloudflared 每次下载“最新版”，没有校验 | 固定一个版本，每个系统都核对 SHA-256。<br>每次启动前再核对一次已安装的文件，被换过就不运行。 |
| 中 | 本机离线语音识别模型只检查文件大小 | 每个文件锁定到模型仓库的固定版本和 SHA-256，不一致就丢弃。<br>已经下载过的模型会自动核对一次，不需要重新下载。 |
| 中 | 打包版软件仍然认一个开发用的环境变量，能让窗口加载别的网页 | 正式版完全忽略它。 |
| 中 | 现场房间没有人数和用量上限：链接泄露后可能被人刷你的翻译费用 | 最多 30 人、同时说话最多 3 人，每部手机的音频流量有上限。<br>同一来源猜错链接 10 次就锁定。<br>房间链接改成 128 位随机码（原来 32 位）。 |
| 中 | 自动构建流程的权限偏大 | 默认只读，只有“发布”这一步能写。<br>所有第三方构建组件都锁定到具体版本（防止被人换掉）。<br>构建工具（Gradle）核对官方校验值。<br>每个发布文件附带 GitHub 的“构建来源证明”。 |
| 低 | 线上会议进行中开现场房间，手机能看到线上会议的记录 | 软件内部直接拒绝：线上会议进行中不能开房间。 |
| 低 | 给 Chrome 插件用的本机服务（127.0.0.1:47811）能被“改了解析的网页”探测到 | 只接受 127.0.0.1 / localhost 的访问，并限制同时连接数。 |
| 低 | 插件后台会接收网页里内容脚本发来的控制消息 | 只接受插件自己页面发来的控制消息。<br>Key 所在的存储区，网页里的内容脚本读不到。 |
| 低 | 安卓 App 的原生接口可以访问任何网址、任何协议 | 只能访问 https / wss。<br>只给我们自己的页面麦克风权限。<br>页面加上内容安全策略（CSP）。<br>限制 WebSocket 单帧大小，防止被恶意服务器撑爆内存。 |
| 低 | 电脑版主进程对界面完全信任 | 麦克风、屏幕等权限只给我们自己的页面。<br>“打开文件”只打开记录类文件（文档、字幕、音视频），其他文件只在文件夹里显示。<br>录音保存位置只能通过“选择文件夹”对话框修改。<br>大模型地址必须是 https（本机 localhost 除外），避免 Key 明文传输。 |

这一轮之前已经做过的加固：

- **Electron 安全开关（熔断）：** 正式版不能被当成普通 Node.js 运行，不接受调试参数和 `NODE_OPTIONS`，只从签过的程序包里加载代码（Mac / Windows 会检查完整性）。
- **页面加载：** 改用软件私有的 `mi-app://` 协议，不再用 `file://`，并测试过不能读到软件目录以外的文件。
- **内部消息：** 只接受软件自己页面发来的。

## 检查过、本来就安全的地方

- **窗口隔离：** 所有窗口都开着沙箱和上下文隔离，没有 Node 权限，有内容安全策略。外部链接一律在浏览器里打开。
- **XSS：** 没有发现跨站脚本漏洞。会议记录、纪要、大模型的输出都按纯文字显示，不会被当成网页代码执行。
- **你的 Key 不会到达界面：**
  - 电脑版用系统钥匙串（safeStorage）加密保存。
  - 界面只知道“填了 / 没填”，日志里的 Key 会被打码。
- **调用系统程序**（朗读、检测会议软件、安装驱动）时都用参数列表，不经过命令行拼接，不能被注入命令。
- **防止路径越界：** 会议记录、录音播放、现场房间的网页、软件页面，都不能读到文件夹以外的东西。
- **离线翻译模型**下载后核对 SHA-256，镜像流程上传前也核对一遍。
- **自然人声模型**（0.9 起）和识别模型一样：每个文件锁定到模型仓库的固定版本和 SHA-256，不一致就丢弃；在单独的低优先级进程里运行，只收到要念的文字，接触不到 Key 和会议记录。
- **本机 AI 翻译模型**（腾讯 Hy-MT2）锁定到模型仓库的固定版本和 SHA-256，下载后核对；它在单独的进程里运行（Linux 上在主进程），只用预编译好的官方 llama.cpp 程序，不会在你电脑上编译任何东西。
- **更新提醒**只提示，不会自动下载或运行任何东西。
- **代码仓库**和全部历史里没有泄露任何密钥。

## 还剩下的风险（已决定暂不处理）

1. **安卓 App 用公开的“社区钥匙”签名**（2026-11-20 决定保持现状）。别人理论上可以做一个签名相同的假 APK，所以**请只从官网或 GitHub Releases 下载**，不要安装聊天群、陌生网站里的安装包。以后需要时，构建流程已经准备好换成私人钥匙（`MI_KEYSTORE_B64` / `MI_KEYSTORE_PASSWORD` / `MI_KEY_ALIAS`）。
2. **电脑版没有付费代码签名**（同日决定暂不处理）。Mac 版用一张固定的自签名证书签名（私钥只在维护者的 Actions Secrets 里，见 `scripts/make-mac-cert.sh`），作用是让 macOS 在更新后记得权限，不代表苹果认证。Mac 第一次打开要在“隐私与安全性”里点“仍要打开”，Windows 会弹 SmartScreen 提示，点“仍要运行”即可。以后可以考虑苹果开发者账号（99 美元/年），或者为 Windows 申请 SignPath 给开源项目的免费签名。在那之前，可以用下面的方法确认下载的是正版。
3. **Linux 上没有系统钥匙串时**，Key 会以“只有你能读”的文件保存（权限 600），而不是加密。Mac 和 Windows 不受影响。
4. **现场房间：**
   - 局域网用的是自签名证书，手机第一次打开会提示“不安全”，这是正常的。
   - 开了“公网链接”时，音频和文字会经过 Cloudflare 的服务器。
5. **会被别人看到的数据：** 你选用的云服务（百炼、Azure、智谱等）会收到你的音频和文字，这是翻译本身需要的。只用免费的离线方案时，翻译都在你自己的设备上完成。

## 怎么确认你下载的是正版

每个版本的发布页都有 `SHA256SUMS.txt`（每个文件的“指纹”）。

**方法一：核对指纹。** 下载后在终端里算一下指纹，和 `SHA256SUMS.txt` 里对应的一行一样就是正版。

Mac：

```bash
shasum -a 256 下载的文件名
```

Windows（PowerShell）：

```powershell
Get-FileHash 下载的文件名 -Algorithm SHA256
```

**方法二：核对构建来源证明。** 装了 GitHub 命令行工具的话，可以确认文件确实是在本项目的 GitHub 自动构建里生成、没被改过：

```bash
gh attestation verify 下载的文件名 --repo Crhis-CP/meeting-interpreter
```
